# TalkingLabs — Setup Guide

This guide walks you through everything needed to build and run TalkingLabs. A physical device is recommended. On Android, the LiteRT runtime also runs on an **arm64** emulator started with enough memory (`emulator -avd <name> -memory 8192`) and `EXPO_PUBLIC_ALLOW_EMULATOR_MODEL_LOAD=true`. The iOS Simulator cannot run `llama.rn`.

---

## Prerequisites

| Requirement | Version | Notes |
|-------------|---------|-------|
| Node.js | ≥ 18 | Check: `node --version` |
| npm | ≥ 9 | Comes with Node |
| Xcode | ≥ 15 | **macOS only** — required for iOS |
| Android Studio | ≥ Hedgehog | Required for Android |
| CocoaPods | ≥ 1.14 | `sudo gem install cocoapods` |
| Expo CLI | Latest | `npm install -g expo-cli` (optional) |
| Device | iOS 16+ or Android 10+ (arm64) | llama.rn does not run on simulators |

## 1. Clone the Repository

```bash
git clone https://github.com/Boadiwaa/talkinglabs.git
cd talkinglabs
```

---

## 2. Install Dependencies

```bash
npm install
```

If you're on macOS and building for iOS, also install CocoaPods dependencies:

```bash
cd ios && pod install && cd ..
```

> **Note:** The `ios/` and `android/` folders are gitignored and will be regenerated by Expo's prebuild step. Run `npx expo prebuild` if they are missing.

---

## 3. Download the Model Weights

The model files are **not included in the repository** (they are gitignored). Both runtimes use Google's Gemma 4 E2B model, packaged differently for each (see [README → Model Runtimes](README.md#model-runtimes)):

| Runtime | File | Size | Source |
|---------|------|------|--------|
| Android `litertlm` (default) | `models/gemma-4-E2B-it.litertlm` | 2.59 GB | [litert-community/gemma-4-E2B-it-litert-lm](https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm) |
| `llama` (iOS, or Android fallback) | `models/gemma-4-E2B-it-Q4_0.gguf` | 2.84 GB | [ggml-org/gemma-4-E2B-it-GGUF](https://huggingface.co/ggml-org/gemma-4-E2B-it-GGUF) |
| `llama` vision projector | `models/mmproj-gemma-4-E2B-it-Q8_0.gguf` | 0.56 GB | same repo; needed for photo parsing |

Sizes are in decimal GB (10⁹ bytes), as Hugging Face and Finder report them. Both repositories are public, so no Hugging Face token is needed.

### Run the download script

```bash
chmod +x scripts/download-models.sh
./scripts/download-models.sh
```

This downloads all three files (~6 GB) into `models/`. To skip the LiteRT file (e.g. iOS only), run `LITERT_MODEL_URL="" ./scripts/download-models.sh`. If `HF_TOKEN` is set, the script sends it with each request.

### Alternative: Manual download

If the script fails, download the files from the repositories above and place them at the paths in the table.

## 4. Run on Device

### iOS (macOS required)

1. Connect your iPhone/iPad via USB and trust the computer.
2. Open Xcode, sign the app with your Apple Developer account:
   - Open `ios/TalkingLabs.xcworkspace`
   - Select the `TalkingLabs` target → Signing & Capabilities
   - Set your Team to your Apple ID (free account is fine for testing)
3. Close Xcode.
4. Build and run:

```bash
npx expo run:ios --device
```

Or use the Xcode Build button directly after the above command generates the project.

### Android

1. Enable Developer Options and USB Debugging on your Android device.
2. Connect via USB.
3. Push the model to the device (required before first run):

```bash
npm run android:push-model
```

This uses `adb push` to copy whichever model files exist in `models/` to `/data/local/tmp`. The app copies them to its private documents directory on first launch, so the device briefly needs free space for two copies (~5.2 GB for the LiteRT file).

4. Create `.env.local` in the project root (see [README → Configuration](README.md#configuration)), for example:

```
EXPO_PUBLIC_MODEL_PROVIDER=local
EXPO_PUBLIC_LOCAL_INFERENCE_RUNTIME=litertlm
```

5. Build and run:

```bash
npx expo run:android
```

> **Tip:** Run `npm run android:check-model` to verify the model was pushed correctly before launching.

## 5. First Launch

On first launch, the app will:

1. Detect the model file in its documents directory.
2. Load the model into memory (30–60 seconds on first load, faster subsequently).
3. Show a progress bar in `ModelStatusBar` while loading.
4. Once ready, the camera button in `LabUploadScreen` becomes active.

If the model fails to load, the app falls back to mock data and regex-based parsing so the UI remains functional.

## 6. Using the App (Demo Flow)

1. **Landing screen** → tap "Get Started".
2. **Register** with basic demographics (name, DOB, sex).
3. **Dashboard** → tap the upload button (bottom nav).
4. **Lab Upload** → choose "Take Photo" or "Upload from Gallery".
   - Point at a printed lab report.
   - The parsing pipeline runs automatically.
5. **Results** → tap any flagged result to see the full AI explanation.
6. **Listen** → tap the speaker icon to hear the explanation in your chosen language (English, French, Akan).
7. **Trends** → visit the Trends tab to see how a value has changed over multiple reports.

### Demo mode (no model required)

The Dashboard pre-loads 5 example patients from `src/data/mockData.js`. You can explore the full UI flow — charts, TTS, AI insight cards — without a model loaded. This is useful for quick evaluation on devices that cannot run the model.

## 7. EAS Build (for distributing to others)

To share a build with testers without asking them to clone and build the repo:

### Setup EAS

```bash
npm install -g eas-cli
eas login
eas init   # Links the project to your Expo account
```

### Configure `eas.json`

Create `eas.json` in the project root:

```json
{
  "cli": {
    "version": ">= 10.0.0"
  },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal",
      "ios": {
        "simulator": false
      }
    },
    "preview": {
      "distribution": "internal",
      "ios": {
        "buildConfiguration": "Release"
      }
    }
  }
}
```

### Build for internal testing

```bash
# iOS — creates a shareable .ipa via TestFlight or direct install link
eas build --platform ios --profile preview

# Android — creates a shareable .apk
eas build --platform android --profile preview
```

> **Important:** The model weights are NOT included in the EAS build. For the `llama` runtime, the app downloads the Gemma 4 GGUF files on first launch if `MODEL_DOWNLOAD_URL` and `MMPROJ_DOWNLOAD_URL` are set in `src/services/LlamaService.js`. There is no equivalent download for the Gemma 4 LiteRT file yet. Without a model, testers get rule-based parsing and the mock data demo mode.

### Share the build

After the build completes on EAS servers:
- **iOS**: Distribute via TestFlight (add tester emails in App Store Connect) or share the install URL generated by EAS.
- **Android**: Share the `.apk` download link. Testers enable "Install unknown apps" on their device.

## 9. Troubleshooting

### "LiteRT model loading crashed the app last time"

The app writes a marker before loading the LiteRT model and clears it after the load returns. If a native crash kills the app mid-load, the next launch skips LiteRT and runs in rule-based mode instead of crashing again. LiteRT is retried automatically when the model file changes or `LITERT_RUNTIME_VERSION` in `src/services/LiteRTService.js` is bumped. To retry manually, clear app storage or call `liteRTService.clearCrashMarker()`.

### LiteRT aborts while loading a Gemma 4 model

Gemma 4 `.litertlm` files need `litertlm-android` 0.10.1 or newer (`modules/expo-litertlm/android/build.gradle`). Version 0.8.0 aborts natively while reading them.

### "Model not found" on iOS

- Confirm `models/*.gguf` files exist locally.
- The Expo config plugin (`plugins/withModelAsset.js`) bundles the model into the native build. If you added the model files after the last native build, run `npx expo run:ios` again (not just `npm start`).

### App crashes immediately on Android

- Ensure the device has at least 4 GB RAM (the model needs ~2 GB to load).
- Try setting `n_gpu_layers: 0` and lowering `n_ctx` in `LlamaService.js` for low-memory devices.

### Model loads but inference hangs

- Check that no other app is running a large model simultaneously (limited RAM).
- Reduce `n_predict` in the LlamaService call for faster (shorter) responses.

### CocoaPods errors on `pod install`

```bash
cd ios && pod repo update && pod install && cd ..
```

### `expo-ocr` not found (autolinking)

- Confirm `app.json` has `"autolinking": { "nativeModulesDir": "./modules" }`.
- Run `npx expo prebuild --clean` to regenerate native folders.

## 10. Environment Notes

- Runtime settings come from `.env.local` (gitignored). Without it, the app defaults to the local provider in `auto` mode. Restart Metro after editing it.
- `HF_TOKEN` (shell variable) is optional and only used by the download script.
- `EXPO_PUBLIC_HF_API_TOKEN` is used at runtime by Akan voice playback, which calls Hugging Face-hosted models and needs internet. English and French playback use on-device `expo-speech`.
- No backend server is required for on-device inference. The optional remote provider (`EXPO_PUBLIC_MODEL_PROVIDER=remote`) needs a Gemma API server you host.
- `EXPO_PUBLIC_` values are compiled into the app bundle. Do not put production secrets in them.
